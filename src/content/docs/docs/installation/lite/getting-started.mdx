This guide assumes a broker started as in <DocLink product={Products.TBMQ} path="installation/lite">Install TBMQ Lite</DocLink>,
on `localhost`, and that you have signed in and set the administrator's password.

## Create client credentials

A new broker has Basic authentication enabled and no client credentials, so it refuses every MQTT client until you
create some:

<Steps>

1. **Open the credentials page.**

   Go to **Authentication** → **Credentials** and click **Add** (+).

2. **Name the credentials.**

   For example, `Getting Started Credentials`.

3. **Set a username and password.**

   This guide assumes `username` and `password`. Leave the authorization rules as they are: the publish and the
   subscribe pattern both default to `.*`, which permits any topic.

4. **Save.**

   Click **Add**. The **Check connectivity** dialog opens with ready-made `mosquitto` commands for these credentials.

</Steps>

TBMQ Lite has one client type, **DEVICE**, so the form has no client type field. Every client that connects with these
credentials is a DEVICE client.

## Publish and subscribe from the web UI

A new broker has a **WebSocket Default Connection** that points at `ws://localhost:8084/mqtt` and subscribes to
`sensors/#` with QoS 1. It needs port `8084` published, as in the install command.

<Steps>

1. **Connect.**

   Go to the **WebSocket Client** page and click **Connect**. The status changes to **Connected**.

2. **Publish a message.**

   Set **Topic** to `sensors/temperature`, enter `32` as the payload, and click the **Send** icon.

3. **Check the result.**

   The message appears twice in the **Messages** table: as **Published**, and as **Received** through the `sensors/#`
   subscription.

</Steps>

## Publish and subscribe from the command line

The examples use the <a href="https://mosquitto.org/" target="_blank" rel="noopener noreferrer">Mosquitto</a> clients.
Run each command in its own terminal, the subscriber first.

```bash
mosquitto_sub -d -h localhost -p 1883 -t sensors/temperature -q 1 -u username -P password
```

```bash
mosquitto_pub -d -h localhost -p 1883 -t sensors/temperature -m 32 -q 1 -u username -P password
```

The subscriber prints `32`. While it is connected, open the **Sessions** page to see its session.

## Keep messages for an offline client

A client that connects with a persistent session (clean session off, a fixed client ID) gets the QoS 1 and QoS 2
messages published while it was offline. TBMQ Lite keeps them on the data volume, so they also survive a restart of
the broker.

<Steps>

1. **Subscribe with a persistent session, then stop.**

   ```bash
   mosquitto_sub -d -h localhost -p 1883 -t sensors/temperature -q 1 -u username -P password -c -i my-device
   ```

   Press **Ctrl+C** once the subscription is acknowledged.

2. **Publish while it is offline.**

   ```bash
   mosquitto_pub -d -h localhost -p 1883 -t sensors/temperature -m 33 -q 1 -u username -P password
   ```

   Optionally restart the broker now with `docker restart tbmq-lite`.

3. **Reconnect with the same client ID.**

   Run the command of step 1 again. The subscriber receives `33`.

</Steps>

Each persistent client keeps at most 10,000 messages by default; see
<DocLink product={Products.TBMQ} path="installation/lite/guarantees-and-limits">Guarantees and limits</DocLink>.

<Aside type="tip">
  If a client cannot connect, open **Authentication** → **Unauthorized clients**: the broker records each refused
  connection with its reason.
</Aside>
