docker run --name tbmq-lite-backup -v tbmq-lite:/data \\
  --entrypoint java thingsboard/tbmq-lite:${TBMQ_LITE_VER} \\

export const restoreCmd = `docker stop tbmq-lite
docker create --name tbmq-lite-restore --user 0:0 -v tbmq-lite:/data \\
  --entrypoint bash thingsboard/tbmq-lite:${TBMQ_LITE_VER} -c 'set -e
    rm -rf /data/restore && mkdir /data/restore
    tar -xzf /tmp/backup.tar.gz -C /data/restore db
    rm -rf /data/db && mv /data/restore/db /data/db && rmdir /data/restore'
docker cp tbmq-lite-backup.tar.gz tbmq-lite-restore:/tmp/backup.tar.gz
docker start -a tbmq-lite-restore
docker rm tbmq-lite-restore
docker start tbmq-lite`;

export const listCheckpointsCmd = `docker run --rm -v tbmq-lite:/data --entrypoint ls \\
  thingsboard/tbmq-lite:${TBMQ_LITE_VER} -l /data/backups`;

export const restoreCheckpointCmd = `docker stop tbmq-lite
docker run --rm -v tbmq-lite:/data -e CHECKPOINT=<checkpoint name> \\
  --entrypoint bash thingsboard/tbmq-lite:${TBMQ_LITE_VER} -c 'set -e
    rm -rf /data/db.restore
    cp -a "/data/backups/$CHECKPOINT" /data/db.restore
    rm -rf /data/db && mv /data/db.restore /data/db'
docker start tbmq-lite`;

TBMQ Lite keeps all its data in the store under `/data/db`: sessions and their queues, retained messages, credentials,
providers, users, settings and statistics. A backup is a consistent copy of that store in one `.tar.gz` archive. The
broker does not back itself up: schedule backups and keep them off the host.

<Aside type="caution">
  Copying `/data` while the broker runs does not give a usable backup: the store's files change underneath the copy.
  Use one of the methods below, or a filesystem snapshot of the whole volume.
</Aside>

A backup holds the BCrypt hashes of the client and user passwords and the broker's token signing key. Store it like
a secret.

## Back up a running broker

### From the UI

Sign in as the system administrator, go to **Settings** → **General**, and click **Download backup** on the **Backup**
card.

### With the REST API

`GET /api/system/backup` streams the same archive. It needs a system administrator's token. One backup runs at a time;
a second request while one runs is refused.

## Back up a stopped broker

The backup command opens the store itself, so it runs only while the broker is stopped; with the broker running it
exits with code 2 and changes nothing. It writes the same archive as the REST API:

<Code code={cliBackup} lang="bash" />

The command runs in a helper container, writes the archive inside it, and `docker cp` copies it to the current
directory. Exit code 0 means the archive is written; the command never overwrites an existing file.

## Restore a backup

The archive holds a `db` directory and a `backup-manifest.json` file with the version that wrote it. A backup from
an older version is upgraded on start; one from a newer version is refused.

<Steps>

1. **Stop the broker.**

2. **Replace the store with the archive's `db` directory.**

   With the backup file `tbmq-lite-backup.tar.gz` in the current directory and the volume `tbmq-lite`. The helper
   container runs as root so that the restored files keep their owner, uid `799`; it unpacks the archive before it
   removes the current store:

   <Code code={restoreCmd} lang="bash" />

3. **Check the log.**

   `docker logs tbmq-lite` shows the broker starting on the restored store.

</Steps>

The restored store brings back the passwords and the token signing key of the backup, so sign in with the
administrator password that was valid when the backup was taken.

## Restore a pre-upgrade checkpoint

Before an upgrade changes the store, the broker takes a checkpoint under `/data/backups`, named
`pre-upgrade-<from>-<to>`. It is consistent and takes almost no space at first, because it shares files with the store.
It protects against a failed upgrade, not against a damaged disk: the shared files are the same files.

List the checkpoints:

<Code code={listCheckpointsCmd} lang="bash" />

To go back to one, replace the store with a copy of it. The checkpoint itself stays untouched:

<Code code={restoreCheckpointCmd} lang="bash" />

Start the image the checkpoint was taken with to stay on the old version, or the new image to upgrade again.

If the store is damaged, the broker refuses to start, and its log lists the checkpoints under `/data/backups` and
these restore steps.
