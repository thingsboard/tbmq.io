## Introduction

By the end of this guide you will have a broker to talk to, a set of MQTT client credentials, and a message
published by one client and received by another — with the client session visible in the TBMQ UI.

Start by choosing where the broker runs:

## Try live demo

The fastest way to try TBMQ is the free public broker at <a href="https://demo.tbmq.io" target="_blank" rel="noopener noreferrer">demo.tbmq.io</a> —
a shared sandbox you can publish to right away.

| Parameter          | Value           |
| ------------------ | --------------- |
| Host               | `demo.tbmq.io`  |
| MQTT port          | `1883`          |
| MQTT over TLS port | `8883`          |
| Username           | `demo`          |
| Password           | *(leave empty)* |

<a href="https://demo.tbmq.io/signup" target="_blank" rel="noopener noreferrer">Sign up</a> for a free account to open the TBMQ UI
and watch your own sessions, subscriptions, and broker statistics as you go.

<Aside type="note">
  The demo UI is read-only: you can observe sessions, subscriptions, and statistics, but not change configuration.
  Skip the [credentials step](#configure-client-authentication-and-authorization) — the `demo` user is already set up for you.
  It is also a shared environment, so treat every topic as public and do not publish sensitive data.
  For TLS connection examples, see the <a href="/live-demo/">Live demo</a> page;
  for full administrative access, [install TBMQ locally](#install-tbmq-locally).
</Aside>

## Install TBMQ locally

This section covers the quickest path to your own broker: Docker on a single host.
For every other option — Docker Compose cluster, Kubernetes, cloud, Helm — see
<DocLink product={props.product} path="installation">Installation options</DocLink>.

### Prerequisites

- <a href="https://docs.docker.com/engine/install/" target="_blank" rel="noopener noreferrer">Docker</a> installed and running.
- At least 2 GB of free RAM.

<ShowFor product={props.product} show={[Products.TBMQ_PE]}>

<ConditionalHeading level={3} id="get-the-license-key" showFor="mqtt-broker-pe">Get the license key</ConditionalHeading>

Have your license key ready before you install — the broker will not start without one.
If you don't have a key yet, visit the <a href="/pricing/?section=tbmq-options" target="_blank" rel="noopener noreferrer">Pricing page</a>
to compare subscription plans and perpetual licenses, and to size your deployment.

</ShowFor>

### Run the install script

<Tabs>
<TabItem label="Linux & Mac OS">

Run the following commands to download and start TBMQ:

<Code code={props.product === Products.TBMQ_PE ? linuxPeInstall : linuxInstall} lang="shell" />

</TabItem>
<TabItem label="Windows">

With Docker Desktop installed, run the steps below in PowerShell.

<Steps>

1. **Open PowerShell as Administrator.**

2. **(Optional) Check the current execution policy.**

   It determines whether PowerShell is allowed to run scripts. If it returns `Restricted`, PowerShell runs no scripts at all.

   ```powershell
   Get-ExecutionPolicy
   ```

3. **(Optional) Change the execution policy.**

   Choose the least permissive setting that lets the install script run and still meets your security requirements.
   `Unrestricted` allows all scripts.

   ```powershell
   Set-ExecutionPolicy Unrestricted
   ```

4. **Download and start TBMQ.**

   <Code code={props.product === Products.TBMQ_PE ? windowsPeInstall : windowsInstall} lang="powershell" />

</Steps>

</TabItem>
</Tabs>

The script downloads `docker-compose.yml` into the current directory, creates the Docker volumes, installs the database,
starts the broker, and then follows the container logs. Press `Ctrl+C` to stop following them — the broker keeps running in the background.

<ShowFor product={props.product} show={[Products.TBMQ_PE]}>

<ConditionalHeading level={3} id="configure-the-license-key" showFor="mqtt-broker-pe">Configure the license key</ConditionalHeading>

The `docker-compose.yml` that the script downloaded ships with a placeholder key, so the broker will not start until you replace it.
Open the file, find the `TBMQ_LICENSE_SECRET` environment variable, replace **YOUR_LICENSE_KEY_HERE** with your license key,
then re-run the script to apply the change:

<Code code="./tbmq-install-and-run.sh" lang="shell" />

</ShowFor>

### Log in to the TBMQ UI

Open **http://localhost:8083** and wait until the services are up. Log in with the default system administrator account:

| Field    | Value                      |
| -------- | -------------------------- |
| Username | `sysadmin@thingsboard.org` |
| Password | `sysadmin`                 |

TBMQ then prompts you to change this password. Set a new one, or click **Skip** to keep the default for now.

## Configure client authentication and authorization

<Aside type="note">
  Using the <a href="https://demo.tbmq.io" target="_blank" rel="noopener noreferrer">demo instance</a>? Skip this section —
  the `demo` credentials are already in place, and the demo UI does not allow changes.
</Aside>

A new installation has <DocLink product={props.product} path="security/authentication/basic">Basic authentication</DocLink> enabled,
while X.509, JWT, SCRAM, and HTTP authentication are switched off. So the broker refuses every client that does not match a
stored credentials record — create one before you connect a client:

<Steps>

1. **Open the credentials page.**

   Go to **Authentication** → **Credentials** and click **Add** (+).

2. **Name the credentials.**

   For example, `Getting Started Credentials`.

3. **Set a username and password.**

   Use values of your choice — this guide assumes `username` and `password`.
   Leave the authorization rules untouched: both the publish and the subscribe pattern default to `.*`, which permits any topic.

4. **Save.**

   Click **Add**. The **Check connectivity** dialog opens with ready-made `mosquitto` commands for the credentials you just created.

</Steps>

## Publishing and subscribing to topics

Now move a message through the broker. You can do it entirely in the browser with the built-in WebSocket client,
or from a terminal with a command-line client.

### From the TBMQ UI

A fresh installation already contains a **WebSocket Default Connection** that points at `ws://localhost:8084/mqtt`
and carries one subscription to `sensors/#` with QoS 1 — enough to publish and receive without any setup:

<Steps>

1. **Connect.**

   Go to the **WebSocket Client** page and click **Connect**. The connection status changes to **Connected**.

2. **Publish a message.**

   In the message composer, set **Topic** to `sensors/temperature`, enter `32` as the payload, and click the **Send** icon.

3. **Check the result.**

   The message shows up twice in the **Messages** table: once as **Published**, and once as **Received** — delivered back to
   the same client through its `sensors/#` subscription.

</Steps>

For connection settings, subscription options, and MQTT 5 message properties, see
<DocLink product={props.product} path="user-guide/ui/websocket-client">WebSocket client</DocLink>.

### From the command line

The examples below use <a href="https://mosquitto.org/" target="_blank" rel="noopener noreferrer">Mosquitto</a> clients — see the
<a href="https://mosquitto.org/man/mosquitto_sub-1.html" target="_blank" rel="noopener noreferrer">mosquitto_sub</a> and
<a href="https://mosquitto.org/man/mosquitto_pub-1.html" target="_blank" rel="noopener noreferrer">mosquitto_pub</a> documentation for the full option list.
Run each command in its own terminal, the subscriber first.

<Tabs>
<TabItem label="Demo instance">

Subscribe to the `sensors/temperature` topic:

```bash
mosquitto_sub -d -h demo.tbmq.io -p 1883 -t sensors/temperature -q 1 -u demo
```

Publish a message to the same topic:

```bash
mosquitto_pub -d -h demo.tbmq.io -p 1883 -t sensors/temperature -m 32 -q 1 -u demo
```

If you signed up for a demo account, log in to <a href="https://demo.tbmq.io" target="_blank" rel="noopener noreferrer">demo.tbmq.io</a>
and open the **Sessions** page to find the session your subscriber just created.

</TabItem>
<TabItem label="Local deployment">

Subscribe to the `sensors/temperature` topic:

```bash
mosquitto_sub -d -h localhost -p 1883 -t sensors/temperature -q 1 -u username -P password
```

Publish a message to the same topic:

```bash
mosquitto_pub -d -h localhost -p 1883 -t sensors/temperature -m 32 -q 1 -u username -P password
```

<Aside type="note">
  Replace `username` and `password` with the credentials you created in the
  [authentication section](#configure-client-authentication-and-authorization).
</Aside>

While the subscriber is connected, open the **Sessions** page and click its row to inspect the session — client type,
subscriptions, and connection details.
