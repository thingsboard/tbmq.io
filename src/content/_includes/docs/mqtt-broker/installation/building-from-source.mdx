This guide covers downloading and building TBMQ from source. Instructions are tested on Ubuntu 22.04 LTS and 24.04 LTS.

The build produces installation packages for Linux and Windows and, optionally, local Docker images. The first build
downloads all dependencies and can take 15 minutes or more; later builds reuse them.

## Required tools

This section describes the build tools required to compile TBMQ from source.

### Java

TBMQ is built using Java 25. Install OpenJDK 25:

```bash
sudo apt update
sudo apt install openjdk-25-jdk-headless
```

Configure your operating system to use OpenJDK 25 by default. Set the default version with the following command:

```bash
sudo update-alternatives --config java
```

Verify the installation:

```bash
java -version
```

```text title="Expected output"
openjdk version "25.0.xx"
OpenJDK Runtime Environment (...)
OpenJDK 64-Bit Server VM (build ...)
```

### Maven

TBMQ requires Maven 3.6.3 or later:

```bash
sudo apt install maven
```

Installing Maven also installs your distribution's default Java runtime. Check that Maven runs on Java 25:

```bash
mvn -version
```

The output must include `Java version: 25`. If it shows another version, follow the [Java instructions](#java) above to
restore Java 25 as the default.

### Git

Install Git to clone the source code:

```bash
sudo apt install git
```

### Docker

Docker is needed only to [build local Docker images](#build-local-docker-images) and to [run the tests](#running-tests).
<a href="https://docs.docker.com/engine/install/ubuntu/" target="_blank" rel="noopener noreferrer">Install Docker</a>,
then make sure your user can <a href="https://docs.docker.com/engine/install/linux-postinstall/#manage-docker-as-a-non-root-user" target="_blank" rel="noopener noreferrer">run Docker without root</a> —
the build talks to Docker as the user who runs Maven.

## Build

From the `tbmq` directory, build the project:

```bash
mvn clean install -DskipTests
```

## Build local Docker images

To also build the Docker images, run the build with the Docker plugin enabled:

```bash
mvn clean install -DskipTests -Ddockerfile.skip=false
```

The build creates the following images, each also tagged `latest`:

<Code code={imagesList} lang="text" />

<Aside type="caution">
  These tags match the images published on Docker Hub, so they replace any copies of those images you have pulled, and
  Docker Compose runs your local build instead. Run `docker pull` with the image name to get the published image back.
</Aside>

## Running tests

Integration tests start their dependencies in Docker containers through Testcontainers, so they need
[Docker](#docker) with access for your user.

<Aside type="tip">
  Main and release branches are already tested in CI — you can skip tests to avoid requiring Docker locally.
</Aside>

Run all unit and integration tests:

```bash
mvn clean install
```

## Tips and tricks

Common fixes for build issues:

- **Clean <a href="https://www.baeldung.com/maven-clear-cache" target="_blank" rel="noopener noreferrer">Maven cache</a>:**
  ```bash
  rm -rf ~/.m2/repository
  ```

- **Clean Gradle cache:**
  ```bash
  rm -rf ~/.gradle/caches/
  ```

- **Clean node modules:**
  ```bash
  rm -rf ui-ngx/node_modules
  ```

- **Build in parallel, format license headers, and build Docker images:**

  ```bash
  mvn -T 0.8C license:format clean install -DskipTests -Ddockerfile.skip=false
  ```
