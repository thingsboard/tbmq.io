This guide describes how to install and start a standalone TBMQ instance using Docker on Linux or macOS.
For cluster installation, see the <DocLink product={props.product} path="installation/cluster/docker-compose-setup">cluster setup page</DocLink>.

## Prerequisites

- At least 2 GB of RAM.
- <a href="https://docs.docker.com/engine/install/" target="_blank" rel="noopener noreferrer">Docker</a> installed.

<Aside type="caution">
  Add your Linux user to the Docker group before running Docker commands.
  For details, see <a href="https://docs.docker.com/engine/install/linux-postinstall/#manage-docker-as-a-non-root-user" target="_blank" rel="noopener noreferrer">Manage Docker as a non-root user</a>.
</Aside>

<details>
<summary>Key configuration points in the <code>docker-compose.yml</code></summary>

- `8083:8083` — exposes the HTTP UI on port 8083;
- `1883:1883` — exposes the MQTT port 1883;
- `8084:8084` — exposes MQTT over WebSockets on port 8084;
- `tbmq-valkey-data:/data` — Valkey data volume;
- `tbmq-postgres-data:/var/lib/postgresql/data` — PostgreSQL data volume;
- `tbmq-kafka-data:/var/lib/kafka/data` — Kafka data volume;
- `tbmq-kafka-secrets:/etc/kafka/secrets` and `tbmq-kafka-config:/mnt/shared/config` — Kafka secrets and configuration volumes;
- `tbmq-logs:/var/log/thingsboard-mqtt-broker` — TBMQ logs volume;
- `tbmq-data:/data` — TBMQ data directory (contains `.firstlaunch` after DB installation);
- `tbmq-ie-logs:/var/log/tbmq-integration-executor` — Integration Executor logs volume;
- `tbmq` — Docker service name;
- `tbmq-integration-executor` — Docker service name of the <DocLink product={props.product} path="integrations" bold={false}>Integration Executor</DocLink>, which runs integrations;
- `restart: always` — auto-restarts TBMQ on system reboot or failure.

<Aside>

</Aside>

Once installation is complete, access the TBMQ UI at `http://{your-host-ip}:8083` in your browser (e.g., **http://localhost:8083**).

**Username:**

**Password:**

On first login, you are prompted to change the default password and re-login with the new credentials.

## Logs, stop, and start commands

To view TBMQ logs:

```bash
docker compose logs -f tbmq
```

To stop the containers:

```bash
docker compose stop
```

To start the containers:

```bash
docker compose start
```

<Code code="./tbmq-upgrade.sh" lang="bash" />

After the database upgrade, the script asks you to confirm removing the stopped `tbmq` container
(`Going to remove …-tbmq-1`). Answer `y`; the script then starts TBMQ on the new version.

The upgrade script stops the `tbmq` service while the upgrade runs and starts it again afterwards, so expect a brief interruption.

<Aside type="tip">
  Each script upgrades from the previous release only, so upgrade one release at a time.
  To upgrade to a specific version (e.g., TBMQ v2.0.0),
  replace the release branch in the command above with the target branch name, e.g., **release-2.0.0**.
</Aside>

## Enabling MQTTS (MQTT over SSL/TLS)

To enable **MQTT over SSL/TLS (MQTTS)** in TBMQ, provide valid SSL certificates and configure TBMQ to use them.

For details on supported formats and configuration options, see the <DocLink product={props.product} path="security/mqtts">MQTT over SSL</DocLink> guide.

**Prepare SSL certificates**

Obtain a valid SSL certificate and private key. For example:

- `mqttserver.pem` — public certificate (may include the full chain)
- `mqttserver_key.pem` — private key

<Aside>
  Self-signed certificates are supported for testing. For production environments, use certificates from a trusted Certificate Authority.
</Aside>

**Mount certificates into the container**

In your `docker-compose.yml`, mount the directory containing the certificates into the `tbmq` service:

```yaml
services:
  tbmq:
    volumes:
      - tbmq-logs:/var/log/thingsboard-mqtt-broker
      - tbmq-data:/data
      - PATH_TO_CERTS:/config/certificates
```

Replace `PATH_TO_CERTS` with the path to your certificate files.

TBMQ runs as the `thingsboard` user (UID `799`) inside the container and must be able to read both files. Private keys
are usually readable only by their owner, so give that user ownership of the files:

```bash
sudo chown 799:799 PATH_TO_CERTS/mqttserver.pem PATH_TO_CERTS/mqttserver_key.pem
```

If TBMQ cannot read a file, it fails to start and logs `Permission denied` for that file.

**Configure environment variables**

Add the following variables to the `tbmq` service environment in `docker-compose.yml`:

```yaml
LISTENER_SSL_ENABLED: "true"
LISTENER_SSL_PEM_CERT: "/config/certificates/mqttserver.pem"
LISTENER_SSL_PEM_KEY: "/config/certificates/mqttserver_key.pem"
LISTENER_SSL_PEM_KEY_PASSWORD: "server_key_password"
```

<Aside type="tip">
  Leave `LISTENER_SSL_PEM_KEY_PASSWORD` empty if your private key is not password-protected.
</Aside>

**Expose the MQTTS port**

In `docker-compose.yml`, add the port to the `tbmq` service:

```yaml
services:
  tbmq:
    ports:
      - "8083:8083"
      - "1883:1883"
      - "8084:8084"
      - "8883:8883"
```

**Restart TBMQ**

```bash
./tbmq-install-and-run.sh
```

Once restarted, MQTT clients can securely connect to **port 8883** using TLS/SSL.
