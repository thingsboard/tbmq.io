This guide describes how to install and start a standalone TBMQ instance using Docker Desktop on Windows.
For cluster installation, see the <DocLink product={props.product} path="installation/cluster/docker-compose-setup">cluster setup page</DocLink>.

The install script runs TBMQ, PostgreSQL, Kafka, Valkey, and the Integration Executor as Docker containers on one host.
Once it is running, TBMQ listens on these ports:

| Port   | Protocol             | Used for                                                                  |
| ------ | -------------------- | ------------------------------------------------------------------------- |
| `8083` | HTTP                 | TBMQ UI and REST API                                                      |
| `1883` | MQTT                 | MQTT clients                                                              |
| `8084` | MQTT over WebSockets | MQTT clients that connect over WebSockets                                 |
| `8883` | MQTTS                | MQTT clients that connect over TLS, once you [enable MQTTS](#enabling-mqtts-mqtt-over-ssltls) |

## Prerequisites

- At least 2 GB of RAM.
- <a href="https://docs.docker.com/desktop/setup/install/windows-install/" target="_blank" rel="noopener noreferrer">Docker Desktop for Windows</a> installed and running.

<Aside title="Port 1883 already in use?">
  If TBMQ is installed on the same host where ThingsBoard is already running, the following error may occur:
  ```
  Error response from daemon: ... Bind for 0.0.0.0:1883 failed: port is already allocated
  ```
  To fix this, change `1883:1883` to a free port (e.g., `1889:1883`) in `docker-compose.yml`, then re-run the script:
  ```powershell
  .\tbmq-install-and-run.ps1
  ```
</Aside>

The example matches the default `docker-compose.yml`, which enables only Basic authentication.

<Aside type="tip">
  If you also use X.509 authentication, set `SECURITY_MQTT_SSL_ENABLED=true`.
  If you use only X.509 authentication, set `SECURITY_MQTT_BASIC_ENABLED=false` and `SECURITY_MQTT_SSL_ENABLED=true`.

**Notes**

- **Required:** If `.tbmq-upgrade.env` is missing, the upgrade script will fail.
- Supported variables:
  - `SECURITY_MQTT_BASIC_ENABLED` (`true|false`)
  - `SECURITY_MQTT_SSL_ENABLED` (`true|false`)
  - `SECURITY_MQTT_SSL_SKIP_VALIDITY_CHECK_FOR_CLIENT_CERT` (`true|false`) — usually `false`

<Aside type="danger" title="Missing values disable authentication">
  A variable missing from the file defaults to `false`, so the upgrade creates that provider disabled. With no provider
  enabled, TBMQ accepts every client without authentication. After the upgrade, check **Authentication → Providers** in
  the TBMQ UI. See the <DocLink product={props.product} path="installation/upgrade-instructions/#upgrading-to-220" bold={false}>2.2.0 upgrade notes</DocLink>.
</Aside>

Once the file is created, proceed with the [upgrade](#run-upgrade).
</details>

## Enabling MQTTS (MQTT over SSL/TLS)

To enable **MQTT over SSL/TLS (MQTTS)** in TBMQ, provide valid SSL certificates and configure TBMQ to use them.

For details on supported formats and configuration options, see the <DocLink product={props.product} path="security/mqtts">MQTT over SSL</DocLink> guide.

<Steps>

1. **Prepare SSL certificates.**

   Obtain a valid SSL certificate and private key. For example:

   - `mqttserver.pem` — public certificate (may include the full chain)
   - `mqttserver_key.pem` — private key

   <Aside>
     Self-signed certificates are supported for testing. For production environments, use certificates from a trusted Certificate Authority.
   </Aside>

2. **Mount certificates into the container.**

   In your `docker-compose.yml`, mount the directory containing the certificates into the `tbmq` service:

   ```yaml title="docker-compose.yml" ins={6}
   services:
     tbmq:
       volumes:
         - tbmq-logs:/var/log/thingsboard-mqtt-broker
         - tbmq-data:/data
         - PATH_TO_CERTS:/config/certificates
   ```

   Replace `PATH_TO_CERTS` with the path to your certificate files.

   TBMQ runs as the `thingsboard` user (UID `799`) inside the container and must be able to read both files.
   If TBMQ cannot read a file, it fails to start and logs `Permission denied` for that file.

3. **Configure environment variables.**

   Add the following variables to the `tbmq` service environment in `docker-compose.yml`:

   ```yaml title="docker-compose.yml"
   LISTENER_SSL_ENABLED: "true"
   LISTENER_SSL_PEM_CERT: "/config/certificates/mqttserver.pem"
   LISTENER_SSL_PEM_KEY: "/config/certificates/mqttserver_key.pem"
   LISTENER_SSL_PEM_KEY_PASSWORD: "server_key_password"
   ```

   Leave `LISTENER_SSL_PEM_KEY_PASSWORD` empty if your private key is not password-protected.

4. **Expose the MQTTS port.**

   In `docker-compose.yml`, add the port to the `tbmq` service:

   ```yaml title="docker-compose.yml" ins={7}
   services:
     tbmq:
       ports:
         - "8083:8083"
         - "1883:1883"
         - "8084:8084"
         - "8883:8883"
   ```

5. **Restart TBMQ.**

   ```powershell
   .\tbmq-install-and-run.ps1
   ```

   Once restarted, MQTT clients can securely connect to **port 8883** using TLS/SSL.

</Steps>
