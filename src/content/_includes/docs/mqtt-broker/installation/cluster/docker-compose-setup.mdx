This guide covers setting up TBMQ in cluster mode using Docker Compose.

The scripts run two TBMQ nodes, two Integration Executors, PostgreSQL, Kafka, and Valkey on one host, with HAProxy in
front of the TBMQ nodes. Clients connect to HAProxy, which listens on these host ports:

| Port   | Protocol                 | Used for                                                                              |
| ------ | ------------------------ | ------------------------------------------------------------------------------------- |
| `80`   | HTTP                     | TBMQ UI and REST API                                                                  |
| `443`  | HTTPS                    | TBMQ UI and REST API over HTTPS; see [Generate certificate for HTTPS](#generate-certificate-for-https) |
| `1883` | MQTT                     | MQTT clients                                                                          |
| `8084` | MQTT over WebSockets     | MQTT clients that connect over WebSockets                                             |
| `8883` | MQTTS                    | MQTT clients that connect over TLS, once you [enable MQTTS](#enable-mqtts-mqtt-over-ssltls) |
| `8085` | MQTT over secure WebSockets | MQTT clients that connect over secure WebSockets, once you enable the TBMQ WSS listener (`LISTENER_WSS_ENABLED`) |

## Installation

<Aside title="Cache deployment">
  The scripts run a single Valkey instance by default. To use a Valkey cluster or Valkey Sentinel instead, set `CACHE`
  in the `.env` file to `valkey-cluster` or `valkey-sentinel` before installing.
</Aside>

<Steps>

1. **Create the Docker volumes.**

   The script creates the volumes and copies the TBMQ, Integration Executor, and HAProxy configuration into them:

   ```bash
   ./scripts/docker-create-volumes.sh
   ```

2. **Install the database.**

   ```bash
   ./scripts/docker-install-tbmq.sh
   ```

   The script finishes with `Installation finished successfully!`.

</Steps>

<Aside title="Port already in use?">
  HAProxy publishes ports `80`, `443`, `1883`, `8084`, `8883`, and `8085` on the host, and the default Valkey service
  publishes `6379`. If another service on the host already uses one of them, the script fails with
  `failed to bind host port … address already in use`. Stop that service, or change the host side of the port mapping in
  `docker-compose.yml` (HAProxy) or `cache/docker-compose.valkey.yml` (Valkey), then re-run the script.
</Aside>

## Running

<Steps>

1. **Start all services.**

   ```bash
   ./scripts/docker-start-services.sh
   ```

2. **Open the UI.**

   Once all services have started, open `http://{your-host-ip}` in your browser (e.g., **http://localhost**).
   You should see the TBMQ login page. MQTT clients connect on port `1883`.

3. **Sign in as System Administrator.**

   Use the default **System Administrator** credentials:

   ```text title="Username"
   sysadmin@thingsboard.org
   ```

   ```text title="Password"
   sysadmin
   ```

4. **Change the default password.**

   On first login, you are prompted to change the default password and re-login with the new credentials.

</Steps>

## Logs, stop, and start commands

```bash title="View TBMQ node logs"
docker compose logs -f tbmq1
```

```bash title="View the state of all containers"
docker compose ps
```

```bash title="View the logs of all services"
docker compose logs -f
```

See the <a href="https://docs.docker.com/compose/reference/logs/" target="_blank" rel="noopener noreferrer">docker compose logs</a> reference for more details.

```bash title="Stop the services"
./scripts/docker-stop-services.sh
```

```bash title="Stop only the TBMQ nodes and Integration Executors"
./scripts/docker-stop-tbmq.sh
```

```bash title="Start the TBMQ nodes and Integration Executors"
./scripts/docker-start-tbmq.sh
```

These two scripts leave PostgreSQL, Kafka, Valkey, and HAProxy running. `docker-start-tbmq.sh` also recreates the TBMQ
containers when their image or `tbmq.env` settings changed.

```bash title="Stop and remove the containers"
./scripts/docker-remove-services.sh
```

The data stays in the Docker volumes, so `./scripts/docker-start-services.sh` brings the cluster back.

```bash title="Remove the Docker volumes (deletes all data)"
./scripts/docker-remove-volumes.sh
```

To apply changes to the configuration files (e.g., `haproxy.cfg` or `logback.xml`), copy them into the volumes:

```bash title="Copy the configuration into the volumes"
./scripts/docker-refresh-config.sh
```

TBMQ re-reads `logback.xml` within 10 seconds. To reload the HAProxy configuration without restarting the container,
send it a HUP signal:

```bash title="Reload HAProxy"
docker exec -it haproxy-certbot sh -c "kill -HUP 1"
```

## Enable MQTTS (MQTT over SSL/TLS)

MQTTS allows clients to connect over an encrypted TLS/SSL channel. There are two common approaches:

- **Two-way MQTTS (Mutual TLS)** — TBMQ terminates TLS; clients must present valid certificates.
- **One-way MQTTS (TLS termination at load balancer)** — HAProxy handles TLS termination and forwards plain MQTT to TBMQ over the internal network.

Both approaches encrypt external connections. Two-way MQTTS adds client certificate verification for higher security; one-way MQTTS simplifies broker configuration and can reuse existing HTTPS certificates.

### Two-way MQTTS

In this configuration, TBMQ handles TLS termination and (optionally) client certificate authentication directly.
This approach is suitable when you want the broker to fully control SSL/TLS and mutual authentication without relying on a load balancer for security.
The default `haproxy.cfg` already forwards port `8883` to port `8883` of the TBMQ nodes without terminating TLS.

For supported certificate formats and options, see the <DocLink product={props.product} path="security/mqtts">MQTT over SSL</DocLink> guide.

<Steps>

1. **Provide SSL certificates.**

   Obtain a valid SSL certificate and private key:

   - `mqttserver.pem` — public certificate (may include the full chain)
   - `mqttserver_key.pem` — private key

   <Aside>
     Self-signed certificates are supported for testing. Use certificates from a trusted Certificate Authority in production.
   </Aside>

2. **Mount the certificates into both TBMQ nodes.**

   In `docker-compose.yml`, uncomment the certificates volume mount in both the `tbmq1` and `tbmq2` services and replace
   `PATH_TO_CERTS` with the path to your certificate files:

   <Code
     code={props.product === Products.TBMQ_PE ? certVolumesPe : certVolumesCe}
     lang="yaml"
     meta={`title="docker-compose.yml" ins={${props.product === Products.TBMQ_PE ? '7,13' : '6,11'}}`}
   />

   Keep the other volume lines of each service as they are.

3. **Let TBMQ read the certificate files.**

   TBMQ runs as the `thingsboard` user (UID `799`) inside the container and must be able to read both files. Private keys
   are usually readable only by their owner, so give that user ownership of the files:

   ```bash
   sudo chown 799:799 PATH_TO_CERTS/mqttserver.pem PATH_TO_CERTS/mqttserver_key.pem
   ```

   If TBMQ cannot read a file, it fails to start and logs `Permission denied` for that file.

4. **Configure environment variables.**

   Edit the `tbmq.env` file and uncomment/configure the following lines:

   ```text title="tbmq.env"
   LISTENER_SSL_ENABLED=true
   LISTENER_SSL_PEM_CERT=/config/certificates/mqttserver.pem
   LISTENER_SSL_PEM_KEY=/config/certificates/mqttserver_key.pem
   LISTENER_SSL_PEM_KEY_PASSWORD=server_key_password
   ```

   Leave `LISTENER_SSL_PEM_KEY_PASSWORD` empty if your private key has no password.

5. **Restart services.**

   ```bash
   ./scripts/docker-start-services.sh
   ```

   Once restarted, MQTT clients can connect securely on **port 8883**.

</Steps>

### One-way MQTTS

TLS is terminated at HAProxy. Clients connect to HAProxy on port 8883, which forwards plain MQTT to TBMQ on port 1883.
You can reuse the same certificate used for HTTPS.

<Steps>

1. **Provide the certificate bundle.**

   HAProxy needs one PEM file with the full certificate chain followed by the private key.

   - If you reuse the certificate from [Generate certificate for HTTPS](#generate-certificate-for-https), `haproxy-refresh`
     already saved this bundle as `/usr/local/etc/haproxy/certs.d/your_domain.pem`.
   - Otherwise, copy your bundle into the HAProxy container:

     ```bash
     docker cp fullchain-and-key.pem haproxy-certbot:/usr/local/etc/haproxy/certs.d/
     ```

2. **Point the MQTTS listener at the bundle.**

   In `haproxy/config/haproxy.cfg`, replace the `mqtts-in` section with:

   ```text title="haproxy.cfg"
    listen mqtts-in
     bind *:${MQTTS_PORT} ssl crt /usr/local/etc/haproxy/certs.d/fullchain-and-key.pem
     mode tcp
     option clitcpka # For TCP keep-alive
     timeout client 3h
     timeout server 3h
     option tcplog
     balance leastconn
     server tbMqtt1 tbmq1:1883 check inter 5s resolvers docker_resolver resolve-prefer ipv4
     server tbMqtt2 tbmq2:1883 check inter 5s resolvers docker_resolver resolve-prefer ipv4
   ```

   Replace `fullchain-and-key.pem` with the actual filename of your certificate bundle.

3. **Apply the configuration.**

   ```bash
   ./scripts/docker-refresh-config.sh
   docker exec -it haproxy-certbot sh -c "kill -HUP 1"
   ```

   MQTT clients can now connect securely on **port 8883**.

</Steps>
