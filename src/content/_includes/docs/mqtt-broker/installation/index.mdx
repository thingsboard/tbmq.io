Every option below installs the same broker on top of Kafka, Valkey and PostgreSQL; what differs is where it runs and
how far it scales. A standalone container is enough to evaluate TBMQ or develop against it; production traffic runs on
a cluster of broker nodes.

## Compare the options

| Option                | Runs on                        | TBMQ nodes | PostgreSQL, Kafka, Valkey                                     | Good for                          |
| --------------------- | ------------------------------ | ---------- | ------------------------------------------------------------- | --------------------------------- |
| Docker standalone     | One host                       | 1          | Containers on the same host                                   | Evaluation and development        |
| Docker Compose        | One host                       | 2          | Containers on the same host                                   | Trying cluster mode               |
| Minikube scripts      | Local Kubernetes               | 2          | Pods in the cluster                                           | Trying Kubernetes deployment      |
| Cloud scripts         | EKS, AKS or GKE                | 2          | Managed services where the guide uses them, the rest in the cluster | Production                 |
| Helm chart            | Any Kubernetes                 | 2          | Your choice: in the cluster or managed services               | Production                        |
